> 版本：2026-08-18 · 规划稿（先规划、后实现，本轮不写代码）
> 上位文档：[产品规划-v2.2](产品规划-v2.2.md)（周期定位、范围边界、验收指标）
> 设计规格：[移动端重设计](产品规划-v2.2-移动端重设计.md)（每个页面长什么样、怎么操作，含线框）
> 本文档把 v2.2 的每一个优化点拆到可执行粒度：现状 → 问题 → 目标 → 改动清单。

## 0. 问题定性：为什么"完全没有可用性"

当前移动端是"桌面版倒进手机"，不是移动产品。核心理由：

1. **信息架构照搬桌面**：桌面侧栏 11 个页面 + 探索/认知两个枢纽（共 23 个目的地）在手机上被塞进 5 个底部 Tab + 顶部横滑胶囊，用户找功能要多跳 1–2 层。
2. **数据密集型页面全部是 820px 宽表**：查询结果、志愿表、排名、专业探索、模拟结果在 320–430px 手机上必须横向拖动，物理上不可用。
3. **工具栏和筛选是桌面横向布局**：志愿表 16 个按钮横滑、查询 8 个筛选字段挤两列、顶栏 3 个按钮在 320px 就溢出。
4. **首屏加载 25MB+ JS 数据**：13 个数据文件全量同步解析（投档线 8.7MB、招生计划 9.5MB、专业库 4MB、院校 3.8MB），中端手机首屏明显卡顿。
5. **弹层/组件是桌面形态**：居中 modal、绝对定位 popover、小号按钮（34px）、10px 标签字号，均不符合触控规范。
6. **桌面已稳定、移动未成形**：v2.1 只做了"个人中心列表化、志愿表卡片化"两块，其余页面仍是桌面布局的缩小版。

结论：v2.2 不是"打磨"，是**移动端可用性重构**。范围仍遵守零功能新增，但允许重构信息架构的移动端呈现层与数据加载方式。

## 1. 设计基线（全局统一）

### 1.1 断点体系（重构，取代现有一堆零散断点）

| 档位 | 宽度 | 定位 |
| --- | --- | --- |
| xs | ≤374px | 小屏手机（iPhone SE/旧安卓/折叠屏短边） |
| s | 375–430px | 常规手机，**基准设计宽度 390** |
| m | 431–719px | 大屏手机/小折叠 |
| t | 720–860px | 小平板/大手机横屏 |
| l | 861–1079px | 平板（竖）/小笔记本 |
| xl | ≥1080px | 桌面，保持 2.1.1 现有视觉 |

规则：所有断点收敛到这套体系；现有 340/520/560/640/720/860/1080 断点按新体系合并重写，避免层层覆盖。

### 1.2 视口与滚动分区

- 手机（≤719px）：`html/body` 锁滚动，`.app` 固定 100dvh，内容区独立滚动；底部导航固定；弹层打开时内容区禁止滚动（滚动穿透必须处理）。
- 平板（720–1079px）：允许整页滚动，弹层用抽屉时仍锁内容。
- 桌面（≥1080px）：维持现状（页面锁定、表格内滚动）。
- 横屏手机（宽 > 高且高度 ≤500px）：用横屏专用布局，见 §6。

### 1.3 触控规范

- 所有可点元素命中区 ≥44×44px（比 2.2 验收的 40 更舒适），视觉可以小（用 padding/margin 扩命中区），间距 ≥8px。
- 相邻按钮最小间距 8px，防止误触；危险操作（清空/删除）二次确认。
- 拖拽仅限桌面；手机一律用"上移/下移/置顶"按钮或长按排序（长按排序需提供视觉反馈）。
- 去掉双击缩放与 300ms 点击延迟；`touch-action: manipulation` 全局。

### 1.4 字号阶梯（可读性）

| 用途 | 手机 | 平板 | 桌面 |
| --- | --- | --- | --- |
| 页面标题 | 18px | 18px | 15px |
| 卡片正文 | 14px | 14px | 13px |
| 数据/标签 | 12px | 12px | 11.5px |
| 极小标签（仅徽章/角标） | 11px | 11px | 10px |

- 数据列全部 `font-variant-numeric: tabular-nums`，等宽数字。
- 允许用户跟随系统字号（去掉对 `-webkit-text-size-adjust` 的硬限制，验证无障碍字体放大不破版）。

### 1.5 动效规范

- 统一 0.12–0.28s、缓动 `cubic-bezier(0.22, 0.61, 0.36, 1)`；位移+淡入为主，不做弹性/缩放花活。
- `prefers-reduced-motion: reduce` 下全部关闭（现状已部分实现，补全所有动画入口）。
- 页面切换手机端用"右滑进入/右滑返回"的二级页动效，桌面保持淡入。

### 1.6 安全区（刘海/全面屏全覆盖）

- 顶栏：`padding-top: env(safe-area-inset-top)`；底栏：`padding-bottom: env(safe-area-inset-bottom)`。
- 全屏二级页、底部抽屉、Toast、分享长图预览同样处理。
- 横屏：左右 `env(safe-area-inset-left/right)` 补足。

### 1.7 弹层体系（手机统一）

| 类型 | 手机 | 桌面 |
| --- | --- | --- |
| 表单/筛选/选择器 | 底部抽屉（底部圆角 18px，拖拽把手） | 居中 modal |
| 详情/阅读/编辑 | 全屏二级页（右滑进入，有返回） | 居中 modal/侧栏 |
| 轻提示/确认 | Toast 顶部下滑；确认框底部 | Toast 底部；居中确认 |
| 菜单 | 底部 ActionSheet | 点击定位 popover |

规则：同一内容在手机只允许一种弹层形态，不再出现居中 modal + 抽屉混用。

## 2. 性能基线（可用性的隐形门槛）

### 2.1 现状

| 文件 | 体积 | 用途 |
| --- | --- | --- |
| data/library-2026.js | 9.5MB | 2026 全量招生计划 |
| data/lines.js | 8.7MB | 2021–2026 投档线 112,224 条 |
| data/major-db.js | 4.0MB | 专业库 965+ 条+聚合 |
| data/schools.js | 3.8MB | 院校库 3100+ 条 |
| 其余 9 个 data 文件 | ~3MB | 排名/白皮书/评估等 |
| 全部 JS | 4.2MB | 12 个页面脚本 |
| assets | 58MB | 图片/字体/壁纸 |

手机首屏 = 同步解析全部 ~25MB JS + 主线程渲染 → 明显卡顿。

### 2.2 目标

- 首屏（工作台）加载：传输 JS ≤1.5MB（gzip 后），解析+执行 ≤500ms（中端机），从点击到可交互 <2s。
- 交互响应：点击到反馈 ≤100ms；列表滚动 60fps。
- 次级页面（查询/排名/专业/院校）数据按需加载，打开时才拉对应数据，加载态有骨架屏。

### 2.3 优化点（编号 P-）

| 编号 | 点 |
| --- | --- |
| P-201 | 数据文件从同步 `<script>` 改为按需异步加载；首屏只带一分一段/分段/白皮书元数据 |
| P-202 | lines.js 按年份切片（2026 单独、历史按需），查询时按筛选年份懒加载 |
| P-203 | library-2026.js 拆分或索引化：首屏不带 9.5MB，院校/专业详情按需取 |
| P-204 | major-db / schools 改为按需 + 增量索引（搜索时先本地索引后取详情） |
| P-205 | 生产开启 gzip（Vercel 默认）+ 静态资源加内容 hash 做长缓存（当前用 ?v= 版本号） |
| P-206 | 图片全部懒加载 + WebP/AVIF 转换 + 尺寸裁剪（assets 58MB → 目标 <15MB） |
| P-207 | 志愿表 80 行卡片 DOM 轻量化（事件委托、行复用），长列表虚拟滚动 |
| P-208 | 白皮书长文分段渲染（按章节懒渲染），避免一次性插入 1000+ 行 DOM |
| P-209 | 列表图片（院校封面/校徽）占位底色 + 骨架屏，弱网降级 |
| P-210 | 测量与预算：引入性能预算检查（脚本体积/首屏时间），防回归 |

## 3. 信息架构（移动端呈现层重构）

### 3.1 现状

- 底部 Tab：工作台 / 志愿表 / 探索 / 认知 / 我的。
- "探索"Tab → hero 枢纽页（6 个宫格卡）→ 子页（顶部胶囊横滑切换）。
- "认知"Tab → 6 个认知子页同构。
- 顶栏：标题 + 智问 + 主题 + 个人快捷（3 个按钮，320px 溢出）。

### 3.2 问题

- 常用功能（查询/探索）被 hero 枢纽挡一层；低频功能（志愿库/模拟/排名）藏在二级，用户找不到。
- 顶部胶囊横滑切换与底部 Tab 并存，层级混乱。
- 顶栏三按钮在窄屏拥挤，且"智问"高频度不高。

### 3.3 目标与改动

| 编号 | 点 |
| --- | --- |
| P-301 | 底部 Tab 保持 5 个：工作台 / 志愿表 / 探索 / 认知 / 我的 |
| P-302 | 手机"探索"Tab 首次进入显示**紧凑宫格**（去掉 hero 大图与长文案），进入子页后记忆位置，下次直达；提供"返回宫格"入口（宫格页顶部小字） |
| P-303 | "认知"Tab 同规则：直达上次子页，宫格仅作首屏/返回层 |
| P-304 | 手机顶栏只保留：页面标题 + 主题切换；"智问"移入"我的→工具"，个人快捷信息并入"我的"Tab 头部 |
| P-305 | 子页间切换（查询/志愿库/模拟/探索/排名/专业）手机端用底部抽屉选择（现顶部胶囊横滑保留在平板档） |
| P-306 | 桌面/平板信息架构不动（侧栏全量导航），只优化手机呈现层 |
| P-307 | 所有页面标题统一：手机顶栏标题 = 页面名 + 小字号副标题（如"数据查询 · 六年投档线"） |

### 8.2 自动化验收（复用现有 headless Chrome 管线）

- 六档宽度 × 全部页面：`scrollWidth ≤ innerWidth`（无横向溢出）、无文字截断。
- 触控目标：手机档所有可点元素命中区 ≥44px（装饰标签白名单外）。
- 交互探针：抽屉/弹层/全屏页打开后边界在视口内、可关闭、滚动不穿透。
- 性能：首屏 JS 传输体积与解析时长打点，超预算 CI 报错。

### 8.3 人工验收清单

- 真机：iPhone（390/430）、安卓（360/412）、平板（768/1024）、折叠屏。
- 核心路径走查：建档 → 查询 → 收藏/加入 → 排序 → 体检 → 模拟 → 分享，全程单手可完成、≤2 跳。
- 桌面 ≥1080 回归：5 个一级页 + 认知子板块截图对比 v2.1.1，无回退。

## 10. 禁止事项（防回归）

- 不新增功能/数据/入口/设置项（含实验开关）；范围仅呈现层、交互容器、加载方式。
- 不改变桌面 ≥1080 的视觉语言与信息架构（只允许 bug 修复与上述触控档位规则）。
- 不引入框架/重写技术栈；保持纯静态单页 + 原生 JS，避免迁移风险。
- 手机不出现 820px 级横滑表（任何页面）；如必须用表，先给卡片/列表方案。
- 不为了触控放大而无差别放大所有按钮（列表密度场景用命中区扩展，不撑高视觉）。
- 每一步改动后跑自动化矩阵，禁止"改完截图一眼看"式交付。
