# 潮汐志愿 · 双轨战略与 v3.x App 化规划

> 2026-08 · 主线：**v2.x 继续做功能与适配（Web），v3.x 独立 App 化（全平台）**
> 两条腿走路：2.x 是"产品试验场"，3.x 是"分发与体验载体"，功能先在 2.x 验证，稳定后合入 3.x。

## 0. 为什么双轨

- Web 迭代快、零安装、适合试验；但体验上限受浏览器限制（离线、推送、系统级集成）。
- App 是长期分发入口：iOS/iPadOS/Android/桌面都有固定使用场景（查数据、改志愿、分享给家长）。
- 数据资产（浙江投档线/白皮书/认知库）是核心，App 只是让它"随处可用"的壳。

## 1. 目标平台矩阵

| 平台 | 优先级 | 关键点 |
| --- | --- | --- |
| iOS / iPadOS | 高 | 离线可用、桌面小组件、分屏适配、App Store 审核 |
| Android 手机 / Pad | 高 | 碎片化适配、国内商店上架、Pad 横屏布局 |
| macOS | 中 | 原生感、菜单栏/通知、与 iOS 共享能力 |
| Windows | 中 | 安装包与自动更新、触屏适配 |

## 2. 技术路线（原生 · 系统级框架）

**UI 完全重构，不复用 Web UI。** 每个平台用系统原生框架，获得该平台最地道的交互、动效与无障碍能力。

| 平台 | 框架 | 说明 |
| --- | --- | --- |
| iOS / iPadOS | SwiftUI | 原生声明式，动效/小组件/分屏天然适配 |
| macOS | SwiftUI（同构） | 与 iOS 共享 SwiftUI 代码与数据层 |
| Android 手机 / Pad | Kotlin + Jetpack Compose | 初期 Material 3 原生体系，后期自定义主题 UI 升级 |

### 2.1 共享层
- 数据/逻辑层跨平台共享（Swift + Kotlin 各自实现，接口同构；或远期 Rust/Core 核心）。
- 数据文件本地化（已离线优先），App 启动零网络。

### 2.2 UI 原则
- iOS/macOS：SwiftUI 默认美学优先，遵循 HIG，不强行品牌化。
- Android：先 Material 3 保证系统一致，UI 升级阶段再叠加潮汐品牌视觉。
- 两平台交互各自原生：iOS 手势/上下文菜单，Android 返回键/长按菜单，不强行统一。

### 2.3 数据与同步
- 本地优先：沿用现有 localStorage/文件结构。
- 同步方案候选：iCloud（苹果生态）、WebDAV/坚果云（通用）、自建轻量后端（远期）。
- 所有同步必须加密；导出/导入兼容现有备份格式。

## 3. 里程碑

### 3.1 MVP（v3.0）
- 移动端双平台（iOS + Android 手机），SwiftUI / Compose 原生重构核心闭环。
- 核心闭环：建档 → 查数据 → 排志愿 → 体检 → 导出分享。
- 离线可用、备份导入导出、主题系统。

### 3.2 v3.1
- iPadOS 分屏适配 + Android Pad 横屏（Compose 自适应布局）。
- macOS 桌面版（SwiftUI 同构，共享 iOS 数据）。

### 3.3 v3.2
- Windows 桌面版（WinUI 3 或 Tauri 单独评估，优先级最低）。
- 系统级能力：通知提醒（志愿日程）、小组件、深链。

### 3.4 远期
- 跨设备同步、多账号（家庭协作）、推送服务。

## 4. 双轨协同规则

- **功能先行**：所有新功能先在 2.x Web 验证；3.x 移植数据逻辑与产品语义，UI 按平台原生重构。
- **数据同源**：同一份数据仓库，两轨共享，禁止分叉。
- **版本对齐**：3.x 大版本与 2.x 功能基线绑定（如 3.0 = 2.x 当前全量功能）。
- **2.x 不降速**：App 化期间 2.x 照常迭代，App 只是多一个出口。

## 5. 风险与边界

- 个人项目双轨维护成本高：优先保证 2.x 稳定，3.x 用 MVP 验证后再投入。
- 商店政策：iOS 审核（离线本地产品友好）、Android 国内商店资质。
- 隐私：数据仅存本机/用户自有云，不接入广告与追踪。
- 仍坚持"永远做浙江产品"：App 化不改变产品边界。
