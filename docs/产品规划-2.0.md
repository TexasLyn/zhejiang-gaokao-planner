# 潮汐志愿 2.0 · 产品设计

> 设计师视角 · 2026-08 · 基于 1.x 完整盘点后的大迭代方案
>
> 一句话定位：从「能填志愿的工具」升级为「帮浙江考生把 80 个志愿填得明明白白的决策工作台」。

## 0. 1.x 盘点（2.0 的地基）

**已经做得很好的**：数据全（6 年投档线、一分一段、选科要求、计划、专业库、榜单、学科评估）、决策工具齐（等位分、波动、梯度体检、选科体检、计划变化、新招标记、模拟录取）、体验完整（弹性拖拽、主题系统、明暗、壁纸、毛玻璃、移动端专属导航）、有真实案例（681/1741 → 南大技科班）。

**2.0 要解决的三个天花板**：

1. **决策有工具、缺"判断"**：现在给你数据和方法，但没给你"结论的把握"——这个志愿到底多稳？方案整体风险在哪？
2. **信息有量、缺"认知"**：数据堆在表格里，缺少院校/专业/城市/就业之间的横向关系。
3. **产品有功能、缺"叙事"**：还没有一个让人一眼记住的定位与品牌故事。

## 1. 定位与北极星

**定位**：浙江考生专属的志愿决策工作台。数据可溯源、决策有依据、体验有质感。

**北极星指标**：一名考生从建档到产出一份「体检全绿」的方案 ≤ 30 分钟，且方案里每一个关键决策（冲稳保、顺序、兜底）都能说出依据。

**三个支柱**：

| 支柱 | 回答的问题 | 2.0 代表能力 |
| --- | --- | --- |
| 决策质量 Decision | 这个志愿多稳？方案风险在哪？ | 录取概率区间、风险地图、策略助手 |
| 认知深度 Insight | 这学校/专业到底怎么样？ | 院校对比、毕业去向标签、城市探索 |
| 体验质感 Craft | 用起来舒不舒服、好不好看？ | 设计系统 2.0、动效规范、品牌叙事 |

## 2. 信息架构重构（4 个一级入口）

现状 9 个板块平铺 + 移动端「更多」抽屉 → 2.0 按考生旅程重组：

```
潮汐志愿 2.0
├── 工作台（默认落地）＝决策驾驶舱
│     档案卡片 · 方案健康分 · 今日待办 · 最近收藏 · 录取轨迹
├── 志愿表（核心编辑器）＝方案 2.0
│     风险地图视图 · 策略助手 · 体检 · 模拟录取 · 快照对比
├── 探索 ＝统一认知入口
│     院校（含对比） · 专业（×院校矩阵） · 城市 · 榜单/学科评估
└── 我的 ＝档案 / 数据 / 设置 / 关于（品牌页）
```

移动端底部导航同步变为 4 个主 Tab（工作台 / 志愿表 / 探索 / 我的），取消「更多」抽屉——探索内部承载全部二级页面。桌面侧栏同构。

## 3. 核心能力规划（按价值排序）

### P0 · 决策引擎（2.0 的主角）

1. **录取概率区间图**：用 2021–2026 六年位次分布（均值 / 中位数 / 极值 / 波动系数）给每个志愿画一条"概率带"，结合当年计划数变化修正，输出文字依据（如"近三年位次稳定在 1600–1900，去年 1882，波动小，属稳档"）。不做伪精确百分比，只给区间与理由。
2. **80 志愿风险地图**：把整个方案画成一张从冲到底的梯度曲线 + 风险色带，一眼看出：哪里太密、哪里有空档、兜底是否安全。
3. **策略助手**：按位次与目标档位生成分配建议（冲/稳/保比例、兜底安全线），检测"第 N 志愿与第 M 志愿重复度过高"、"倒挂"、"空档过大"，给出可执行替换建议。
4. **方案快照对比**：填报前冻结 A/B 方案，并排对比健康分、风险地图与模拟结果。

### P1 · 认知层（把信息变成理解）

5. **院校对比**：2–3 所院校并排（分数/位次、学科、就业、城市、宿舍、学费）。
6. **毕业去向标签**：深造率、国家电网、考公、大厂、师范认证等标签体系（复用已入库的推免率、国网名单、就业方向数据）。
7. **城市探索**：按城市看院校集群、专业供给与生活维度（杭州/宁波/北京/上海……）。
8. **专业 × 院校矩阵**：专业页直接看"这个专业谁最强 + 需要多少分 + 毕业去向"。
9. **学长学姐说**：把已收集的学长分享 / 深度解读 docx 结构化，挂在专业与院校卡片上，标注整理年份与出处。

### P2 · 协作与数据平台（让产品更完整）

10. **家长/老师审阅**：只读分享（长图 / PDF / 本地链接）+ 批注层，互不覆盖。
11. **数据版本化**：数据字典 + 年度一键更新包（2027 发布时替换），更新日志与旧数据对比。
12. **云备份（可选）**：WebDAV / 网盘自动备份，仍以本地为主。
13. **PWA 离线 + 可选桌面壳**：可安装、可离线，保持"打开即用"。

### P3 · 长期延展

14. **选科决策**（高一高二）：专业限科反查（"想学医要选什么"）、轻量生涯兴趣自测。
15. **AI 助手「智问」**：先做规则问答（政策、数据查询、方案解释），LLM 作为可选增强，避免花哨聊天感。
16. **录取纪念**：录取结果生成分享卡片——你自己的「681 分 → 南大技科班」就是最佳模板。

## 4. 设计系统 2.0

- **令牌化**：语义色（accent / success / warn / danger / 位次档），明暗双轨，主题可扩展（现有 9 套 + 壁纸 + 毛玻璃开关全部收敛进令牌）。
- **字体阶梯**：标题标宋 / 南雍紫楷书（已有）；表格与数据引入等宽数字（tabular-nums 体系化）；正文保持系统字体。
- **组件规范**：卡片、表格、胶囊、弹层、底部抽屉、空状态（真实文案 + 极简插画，不放装饰图）。
- **动效规范**：150–300ms 标准缓动；拖拽弹性（已有）复用为全局语言；明暗过渡；页面转场；风险地图 / 概率图专属动画。
- **插画体系**：时段插画（普通主题）、NJU 专属（南雍紫）、空状态轻插画，三套并存有明确使用场景。
- **品牌叙事**：关于页升级为品牌页——潮汐志愿标识、数据来源可信度说明、你的录取轨迹（真实案例背书）。

## 5. 技术演进建议

- **保持 local-first**：数据留在本机，打开即用，这是产品的灵魂，2.0 不破坏它。
- **轻量构建化**：1.x 是单 HTML，2.0 拆出清晰的模块层（数据层 / 引擎层 / UI 层），输出仍是静态站，可选择性加 PWA。
- **性能**：虚拟滚动（>1000 行）、概率计算缓存、增量渲染。
- **数据层**：版本化数据包 + 年度更新流程（发布 2027 数据时一键替换）。

## 7. 不做的事（设计原则）

- 不做伪精确录取百分比——只给区间 + 依据。
- 不做强制登录——账号可无，云备份可选。
- 不堆功能——每个新功能必须回答"它提升了哪个决策的质量"。
- 不做与浙江规则冲突的通用化——先浙江，再考虑模板化。

## 8. 需要拍板的决策点

1. **产品形态**：继续"打开即用的本地工具"（推荐）还是上带账号的云版？
2. **概率表达**：接受"区间 + 文字依据"（推荐），还是想要数字百分比？
3. **信息架构**：4 个一级入口（工作台/志愿表/探索/我的）是否认同？
4. **AI 助手**：2.0 就上，还是先做纯规则问答（推荐先规则）？
5. **品牌化**：关于页升级品牌叙事 + 你的录取轨迹案例，是否 OK？
